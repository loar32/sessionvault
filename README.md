# SessionVault

Offline protection for app sessions against infostealers on Windows.

Статус: v0.5, ранняя версия. Защищены Telegram Desktop и браузеры Chrome, Edge, Brave. Защищаются файлы сессии, а не окно запущенного приложения (см. «Ограничения»).

## Как это работает

- Приложение запускается от отдельной учётки `vault`, а его данные лежат в папке, закрытой для остальных учёток.
- Пока приложение закрыто, данные зашифрованы (AES-256-GCM, ключ выводится из мастер-пароля через Argon2id).
- Служба Windows расшифровывает данные при запуске и шифрует обратно при выходе. Мастер-пароль вводится в окне службы.
- Хранилище защищено от отката: номер каждой записи входит в проверку подлинности, подмена `data.enc` на старую копию или параметров ключа отклоняется. Предыдущий архив хранится как `data.enc.bak`; вернуть его можно командой `sessionvault restore-backup telegram` (от администратора, нужен мастер-пароль).
- Мастер-пароль при создании хранилища — не менее 10 символов.
- Запросы на запуск и окно пароля ограничены по частоте, чтобы процесс вашей сессии не мог засыпать вас окнами.
- Сети в программе нет.

## Установка

Запустите `SessionVaultSetup.exe` под обычной (не администраторской) учётной записью и подтвердите UAC. В конце мастер предложит защитить сессию Telegram: закройте Telegram и задайте мастер-пароль. Запускайте Telegram из иконки SessionVault в трее.

Удаление через «Приложения» возвращает данные Telegram на прежнее место; для этого нужен мастер-пароль.

## Браузеры: Chrome, Edge, Brave

Команда от администратора: `sessionvault protect chrome` (или `edge`, `brave`; флаг `-yes` пропускает вопрос). Браузер должен быть установлен для всех пользователей (в Program Files) и закрыт. Что происходит:

- Браузер запускается от учётки `vault` с профилем в закрытой папке; пока он закрыт, профиль зашифрован. Запускайте его из иконки SessionVault в трее: пункты меню появляются для каждого защищённого приложения. Кэши в архив не попадают.
- Профиль создаётся новым: куки и пароли браузера зашифрованы ключом вашей учётной записи (DPAPI), и `vault` их прочитать не может. Входы придётся сделать заново (синхронизация аккаунта вернёт закладки и пароли).
- Прежний профиль в вашей учётной записи **удаляется** после подтверждения (нужно ввести `delete`): пока он на месте, стилер читает его как раньше. На его месте остаётся приманка в стиле Chromium (`Local State`, `Default\Network\Cookies`, `Default\Login Data`).
- Обычный браузер из вашей учётной записи (ссылка в письме, автозапуск, ярлык) создаст настоящий профиль на месте приманки. Подписанные exe Chrome, Edge и Brave в белом списке приманки, поэтому тревоги не будет, но такой профиль уже не защищён. Открывайте браузер из трея.

## Приманка

На прежнем месте `tdata` лежит папка с похожей структурой и случайным содержимым. Windows ведёт аудит чтения этой папки, а служба разбирает событие 4663 из журнала Security. Если приманку читает посторонний процесс (не из белого списка), служба сразу закрывает защищённые приложения, шифрует данные, стирает ключи из памяти и показывает окно тревоги с процессом, путём к exe и SHA-256. Иконка в трее становится красной, запись остаётся в `C:\ProgramData\SessionVault\alerts.log` (читать: `sessionvault alerts` от администратора).

Белый список по умолчанию: поиск Windows и антивирус Windows Defender. Свои записи добавляются в `config.json` в поле `decoy_allow`: `{"path": "C:\\Путь\\программа.exe", "publisher": "Издатель"}`. Вне каталогов Windows и Program Files запись принимается только с издателем, подпись проверяется офлайн.

## Ограничения

- Аудит срабатывает после чтения: стилер успевает прочитать приманку, но не настоящие данные. Если групповая политика или администратор отключили аудит файловой системы, приманка молчит; `sessionvault alerts` показывает, работает ли аудит.
- Тревога может не сработать, если приманку читают через жёсткую ссылку (hardlink) на её файл вне папки или после переименования папки: аудит записывает в журнал новый путь, и служба не узнаёт в нём приманку. Это ограничение планируется исправить позже.
- Приманка не защищает от процесса из белого списка, в который внедрён чужой код.

- Защищает от стилеров в обычной учётке. Администратор обходит права файлов, поэтому программа не ставится под учётку-администратора.
- Пока Telegram запущен, его данные открыты для самого Telegram. Файлы остаются закрытыми для других учёток, но процесс вашей сессии видит окно Telegram, экран, буфер обмена и может отправлять в окно нажатия клавиш. Защита — от кражи файлов сессии, а не от управления запущенным приложением.
- Пока хранилище разблокировано (по умолчанию 15 минут после последнего закрытия), процесс вашей сессии может запустить Telegram командой `run` без нового ввода пароля. Данные он при этом не получает.
- Мастер-пароль вводится на обычном рабочем столе: кейлоггер в вашей сессии может его перехватить. Исправление — Windows Hello (запланировано).
- Установщик проверяет подпись `Telegram.exe` (издатель Telegram FZ-LLC); неподписанный или чужой файл установку останавливает.
- Откат сразу обоих файлов хранилища (`data.enc` и `vault.json`) виден только при наличии прав администратора, а с ними защита всё равно обходится.
- Данные запущенного приложения живут в памяти процесса `vault` и могут попасть в файл подкачки, файл гибернации и аварийные дампы. Включите BitLocker (или шифрование диска), иначе с диска их читает тот, у кого есть физический доступ к компьютеру.
- Если приложение, запущенное от `vault`, взломано (например, через уязвимость в браузере), оно получает те же возможности в вашем сеансе, что и обычная программа: окно, ввод, экран, общие имена объектов `Local`. Держите браузеры обновлёнными.

## Проверка защиты

`access-check` запускается из обычной учётки и пытается прочитать данные, память процесса и управлять службой через pipe; любое успешное чтение — ошибка.
