# SessionVault

Offline protection for app sessions against infostealers on Windows.

Статус: v0.4.1, ранняя версия. Защищён Telegram Desktop.

## Как это работает

- Приложение запускается от отдельной учётки `vault`, а его данные лежат в папке, закрытой для остальных учёток.
- Пока приложение закрыто, данные зашифрованы (AES-256-GCM, ключ выводится из мастер-пароля через Argon2id).
- Служба Windows расшифровывает данные при запуске и шифрует обратно при выходе. Мастер-пароль вводится в окне службы.
- Сети в программе нет.

## Установка

Запустите `SessionVaultSetup.exe` под обычной (не администраторской) учётной записью и подтвердите UAC. В конце мастер предложит защитить сессию Telegram: закройте Telegram и задайте мастер-пароль. Запускайте Telegram из иконки SessionVault в трее.

Удаление через «Приложения» возвращает данные Telegram на прежнее место; для этого нужен мастер-пароль.

## Приманка

На прежнем месте `tdata` лежит папка с похожей структурой и случайным содержимым. Windows ведёт аудит чтения этой папки, а служба разбирает событие 4663 из журнала Security. Если приманку читает посторонний процесс (не из белого списка), служба сразу закрывает защищённые приложения, шифрует данные, стирает ключи из памяти и показывает окно тревоги с процессом, путём к exe и SHA-256. Иконка в трее становится красной, запись остаётся в `C:\ProgramData\SessionVault\alerts.log` (читать: `sessionvault alerts` от администратора).

Белый список по умолчанию: поиск Windows и антивирус Windows Defender. Свои записи добавляются в `config.json` в поле `decoy_allow`: `{"path": "C:\\Путь\\программа.exe", "publisher": "Издатель"}`. Вне каталогов Windows и Program Files запись принимается только с издателем, подпись проверяется офлайн.

## Ограничения

- Аудит срабатывает после чтения: стилер успевает прочитать приманку, но не настоящие данные. Если групповая политика или администратор отключили аудит файловой системы, приманка молчит; `sessionvault alerts` показывает, работает ли аудит.
- Тревога может не сработать, если приманку читают через жёсткую ссылку (hardlink) на её файл вне папки или после переименования папки: аудит записывает в журнал новый путь, и служба не узнаёт в нём приманку. Это ограничение планируется исправить позже.
- Приманка не защищает от процесса из белого списка, в который внедрён чужой код.

- Защищает от стилеров в обычной учётке. Администратор обходит права файлов, поэтому программа не ставится под учётку-администратора.
- Пока Telegram запущен, его данные открыты для самого Telegram; защита действует, когда он закрыт.
- Мастер-пароль вводится на обычном рабочем столе: кейлоггер в вашей сессии может его перехватить. Исправление — Windows Hello (запланировано).
- Подпись Telegram.exe при установке не проверяется.

## Проверка защиты

`access-check` запускается из обычной учётки и пытается прочитать данные, память процесса и управлять службой через pipe; любое успешное чтение — ошибка.
