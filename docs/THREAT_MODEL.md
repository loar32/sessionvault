# Модель угроз SessionVault

[English](THREAT_MODEL.en.md) · Русский

Документ описывает, от кого и от чего защищает SessionVault, на чём держится защита и что она не закрывает. Принцип проекта: защита держится на архитектуре, а не на секретности; код открыт, и читать его могут и защитники, и злоумышленники.

## Что защищаем

Файлы сессии приложений на диске: Telegram Desktop (`tdata`), профили Chrome, Edge, Brave, Discord и добавленных вручную приложений (cookies, токены, локальные базы). Цель: чтобы украденные файлы нельзя было открыть на другом компьютере и чтобы кража была заметна.

## От кого

Основной противник — **инфостилер**: вредоносная программа, запущенная в вашей обычной учётке Windows (из вложения, «кряка», расширения браузера, приёма ClickFix), без прав администратора и без драйвера. Она обходит стандартные места данных, читает файлы и память процессов с правами пользователя и отправляет добычу по сети.

Вне модели (защита их не останавливает, подробнее в README, «Границы защиты»):

- администратор, драйвер ядра, физический доступ к незашифрованному диску;
- вредонос, который сам управляет запущенным приложением (окно, ввод, экран, буфер обмена);
- ClickFix: вы сами запускаете чужую команду с вашими правами;
- уязвимость в самом приложении (браузере), если её используют, пока оно запущено.

## Как устроена защита

| Мера | От чего |
|---|---|
| Данные лежат зашифрованными (AES-256-GCM, ключ из мастер-пароля через Argon2id), номер каждой записи входит в проверку подлинности | кража файлов; подмена архива старой копией (откат) |
| Расшифрованные данные живут только в рабочей папке, доступной одной учётке `sv-<имя>`; после закрытия приложения шифруются и удаляются | чтение данных стилером из основной учётки; чтение данных соседнего приложения |
| Каждое приложение под своей учёткой без прав администратора, запрет запуска файлов из своей папки, запрет интерпретаторов и сетевой заслон для утилит | запуск сохранённого exe и скриптов, вынос данных системными утилитами |
| Приманка на прежнем месте данных + аудит Windows | стилер, обходящий стандартные пути: прочитанная приманка закрывает приложения, шифрует данные, стирает ключи и поднимает тревогу |
| Ключ хранилища в памяти службы SYSTEM; блокировка при Win+L, смене пользователя, сне, бездействии | ключ у стилера в сессии пользователя |
| Вход через Windows Hello (ключ у учётки, в TPM) и FIDO2/YubiKey, ключ восстановления | подсмотр пароля кейлоггером; потеря пароля |
| Журнал чтения памяти защищённых приложений | разбор инцидента, без тревог |
| Проверка системных мер (Defender, BitLocker, HVCI, Secure Boot) | пользователь не знает, чего не хватает; исправления только по явной команде |
| Подпись профилей (HMAC), подпись Authenticode для запускаемых exe | подмена профиля и exe под защитой |

## Границы доверия

- **SYSTEM-служба** — единственный, кто держит ключи. Её интерфейс (закрытый pipe) принимает только имя профиля, без аргументов, и не выдаёт расшифрованные данные.
- **Основная учётка** (не администратор) — недоверенная среда: стилер работает именно в ней. Она не читает хранилище, рабочие папки и пароли учёток приложений (`accounts.json`, закрыт для неё и защищён DPAPI).
- **Учётки `sv-<имя>`** — недоверенные друг для друга: взломанное приложение не должно читать данные соседа.
- **Окна пароля, тревоги и Hello** запускает служба в сессии пользователя от SYSTEM: процессы пользователя не могут их читать и подменять (UIPI).
- **Сеть**: в программе нет сетевых вызовов; брандмауэр дополнительно запрещает ей любой выход.

## Известные ограничения

Полный список — в README («Границы защиты», «Ограничения приманки»). Главные: защита файлов сессии, а не окна запущенного приложения; расшифрованные данные лежат в рабочей папке, пока приложение запущено; администратор и драйвер ядра её обходят; не проверено на железе (YubiKey, отпечаток/лицо, сон, RDP) и с настоящими Discord и Steam; установщик не подписан сертификатом.

## Как проверить

- `access-check` (из каталога сборки) пробует прочитать данные, память процесса и управлять службой из обычной учётки; успешное чтение — ошибка.
- Полный автотест службы и установщика в Hyper-V ВМ: `tools/vm/run-test.ps1`, `tools/vm/run-installer-test.ps1`.
- CI: `go vet`, `golangci-lint`, `go test`, `govulncheck`, проверка «ноль сети», CodeQL.
